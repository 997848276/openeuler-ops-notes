# day27 · 启动流程与故障修复（引导解剖 / fstab 零重启演练 / 慢启动三工具）

> 主线：之前都在讲"跑起来之后怎么查"，今天补"跑不起来/起来慢怎么办"。引导五段：固件(BIOS/UEFI) → GRUB2 → kernel+initramfs → systemd(PID 1) → target。**1~3 挂=进不去（救援修）；4~5 挂=进得去（查服务）**。

## 一、开机耗时侦察
```bash
systemd-analyze                             # 21.001s = kernel 1.794 + initrd 2.644 + userspace 16.562
systemd-analyze blame | head -8             # 榜首 mnt-nfs\x2d254.mount 11.598s
systemd-analyze critical-chain multi-user.target
grubby --info=ALL                           # 4 条目：运行中/旧内核/rescue 救援内核
```
- critical-chain：multi-user ← nginx ← remote-fs ← NFS(@3.484+11.598) ← network-online——_netdev 只并行、不豁免
- 起不来可回退旧内核/rescue = 底气

## 二、BIOS 还是 UEFI
```bash
ls /sys/firmware/efi        # 不存在 = BIOS/Legacy
ls /boot/grub2/             # i386-pc 目录 = BIOS 实锤
ls /boot/loader/entries/    # 空：BLS 布局是 UEFI 特产
lsinitrd | grep -i lvm      # lvm 二进制+rules+parse 脚本
```
- grub.cfg linux 行 = /proc/cmdline 源头（root=/dev/mapper/openeuler_bogon-root）
- ★initramfs=开根脚手架：root 在 LVM 上必须带 lvm 全套钥匙

## 三、fstab→systemd 翻译
```bash
systemctl cat 'mnt-nfs\x2d254.mount'   # 自白书：generated by systemd-fstab-generator
ls /run/systemd/generator/local-fs.target.requires/   # defaults 住这（连坐）
ls /run/systemd/generator/local-fs.target.wants/      # nofail 住这（放行）
```
- ★nofail 不改挂载行为，只改"谁陪葬"；/run 层 unit 重启即焚、按 fstab 现捏

## 四、fstab 零重启故障演练
```bash
两条坏 UUID（bad1=defaults / bad2=nofail）→ daemon-reload
sudo systemctl start local-fs.target   # rc=1 dependency job failed
sudo systemctl start mnt-bad1.mount    # rc=1：.device 永不到场，依赖先死
sudo systemctl start mnt-bad2.mount    # nofail 也救不了自己
```
- ★"A dependency job failed" ≠ unit failed：--failed 查无此人（unit 保持 inactive dead）
- ★start 失败 ≠ target failed（仍 active）；真重启 target 从未起来才进 emergency
- mount -a 静默 = stderr 先冲刷+stdout 全缓冲+tail 切片；真 rc=${PIPESTATUS[0]}=64；mount 判词不完整问 systemd

## 五、慢启动三工具三面孔（lab-slow 15s）
```bash
Type=oneshot + ExecStart=/usr/bin/sleep 15 + RemainAfterExit → enable → time start = 15.048s
systemctl show -p ExecMainStartTimestampMonotonic -p ExecMainExitTimestampMonotonic  # 差=15.048s
systemd-analyze blame                              # ★查无此人
systemd-analyze critical-chain lab-slow.service    # ★+15.011s 有账
systemd-analyze plot > /tmp/boot.svg               # SVG grep lab-slow = 6 处
```
- ★blame=开机事务账本 / critical-chain=任意 unit / plot=全画布——查启动耗时别只盯 blame
- enable=建软链、disable=拆同一根链；enable 未重启=账本外房客

## 六、automount 与时钟案
```bash
sudo sed -i 's/defaults,_netdev/defaults,_netdev,x-systemd.automount/' /etc/fstab
sudo systemctl status 'mnt-nfs\x2d254.automount'   # ★转义名单引号
sudo systemctl enable --now chronyd; sudo chronyc makestep   # 200 OK
```
- NFS 11.6s 正解=automount（先挂空牌子谁访问谁现场挂）；critical-chain 是上次开机的账，收益重启兑现
- ★时钟案：chronyd enabled 但 stopped（配好≠在跑）→ makestep 归位；时钟=时间类排查的底层可信度

## 七、坑位速查
| 坑 | 正解 |
|---|---|
| 非 sudo systemctl 连不上 bus | 128 上一律 sudo |
| 依赖 job 失败=unit failed？ | 账在 .device 头上，--failed 查无此人 |
| nofail 救 mount？ | 只救 target |
| mount -a 没报错 | tail 切片+缓冲顺序；PIPESTATUS=64 |
| blame 查无手动服务 | 只记开机事务；critical-chain/plot |
| sed \1 复制翻车 | 简单替换+grep 验原文 |
| unit 名查不到 | 单引号包 \x2d 转义名 |
| chronyd enabled=准点？ | enabled≠running；date 对表 |

## 面试一句话
> "开机故障先分界：固件/GRUB/内核挂了进不去要救援，systemd/target 挂了进得去用 journalctl。fstab 写错不赌重启——generator 把条目翻译成 mount unit，defaults 进 requires（挂不上拖死 target，真重启即 emergency）、nofail 进 wants（只自己 failed），零重启可预演；注意依赖 job 失败≠unit failed。开机慢三件套：blame 只记开机事务、critical-chain 查任意 unit、plot 出瀑布——本机 21 秒 NFS 占 11.6 秒，正解 automount。钟不准一切时间证据作废——chronyd 配了不等于在跑，先 date 对表。"
