# day39 · NetworkManager 与 nmcli：分清四本账，治"生效轴混线"（2026-10-21 · 128 oe-base 24.03）

## 一 四本账（本章靶子）

| 账本 | 谁写 | 怎么看 | 类比 |
|---|---|---|---|
| 连接配置 profile | nmcli mod/add | 配置文件 | 入职登记表 |
| NM 运行态 | NM 守护进程 | `nmcli con show` | HR 系统状态 |
| 内核实际 | NM 拍进内核 | `ip addr` / `ip route` | 人实际在工位上 |
| 包的通行证 | **firewalld（另一条轴）** | `firewall-cmd --list-all` | 门卫放行名单 |

**记忆钩子：nmcli 管"你是谁"（IP/网关/DNS），firewalld 管"你能不能过"——两条轴，别串线。**

## 二 只读侦察

```bash
nmcli device status        # ens33 connected；lo 是 connected (externally)（NM 认得但没建 profile）
nmcli connection show      # profile 名就叫 ens33，UUID=0ca7cc04-…
ip -br addr && ip route    # default via 192.168.252.2 proto static（DHCP 会写 proto dhcp）
ls -l /etc/resolv.conf     # "# Generated by NetworkManager"——生父=NM
```

⭐ resolv.conf 里的 114/8.8.8.8 与 254 默认 bridge 容器抄的一模一样——容器抄宿主、宿主是 NM 写的。

## 三★ profile 真身：ifcfg 兼容层 + keyfile 只收新住户

- **打脸**：以为 24.03 全面 keyfile → `/etc/NetworkManager/system-connections/` **是空的**；ens33 住**老格式** `/etc/sysconfig/network-scripts/ifcfg-ens33`（BOOTPROTO=none=manual、IPADDR/PREFIX/GATEWAY、DNS1/DNS2、ONBOOT=yes）。
- `nmcli -g connection.filename` → **invalid field**（老语法，新版 NM 白名单里没有）——**报错即文档**。
- **找配置三板斧**：①拿 UUID 当指纹 `grep -rl '<UUID>' /etc/`（唯一、不依赖版本）→ ②问程序（`systemctl cat`）→ ③man 的 FILES 段。
- **新连接走 keyfile**（dummy 实验的 lab0.nmconnection）——**同机两种格式并存：老住民赖 ifcfg，新住户进 keyfile**。

## 四★★ 生效轴现场（dummy 网卡实验，零打脸）

```bash
sudo ip link add dummy0 type dummy
sudo nmcli con add type dummy ifname dummy0 con-name lab0 ipv4.method manual ipv4.addresses 10.66.0.1/24 autoconnect no
sudo nmcli con up lab0 && ip -br addr show dummy0     # → 10.66.0.1/24
sudo nmcli con mod lab0 ipv4.addresses 10.66.0.2/24   # 静默成功
ip -br addr show dummy0                              # ★还是 10.66.0.1/24！
sudo nmcli con up lab0                               # 重新激活才落地
ip -br addr show dummy0                              # → 10.66.0.2/24 ✅
sudo nmcli con del lab0; sudo ip link del dummy0     # 清理
```

**`nmcli con mod` = 改员工手册（≈firewall-cmd --permanent）；`nmcli con up` = 重新入职才按新手册办事（≈--reload）。同一条生效轴，两套工具，一个道理。**

## 五 分界表（治混线的判决书）

| 需求 | 归谁 | 工具 | 生效动作 |
|---|---|---|---|
| 改 IP/掩码/网关 | NetworkManager | `nmcli con mod` + `con up` | mod 改登记表，up 才生效 |
| 改 DNS | NetworkManager（写 resolv.conf） | `nmcli con mod ... ipv4.dns` | 同上 |
| 端口放行/拒绝 | firewalld | `--add-port` | --permanent 写盘 + --reload 进内核 |
| 端口转发 DNAT | firewalld | `--add-forward-port` | 同上 |

**保险丝**：远程改主网卡 IP = 自断 SSH；实验走 dummy 接口，生产走带外控制台。

## 六 坑位速查

| # | 现象 | 正解 |
|---|---|---|
| 1 | 改了 mod 不生效 | mod 只改登记表，要 `con up` |
| 2 | 找不到 profile 落盘位置 | UUID 搜真身；connection.filename 新版不认 |
| 3 | 教程教的 ifcfg 不适用 | 新连接走 keyfile，ifcfg 只是兼容层 |
| 4 | `grep ipv4` 被 head 截光 | 锚定 grep：`grep -E '^ipv4\.(method\|addresses\|gateway\|dns)'` |
| 5 | 远程改主网卡锁死自己 | 用 dummy/次要接口，带外控制台 |

## 七 面试一句话

> 「NetworkManager 要分清几本账：nmcli con show 看运行态、配置文件看落盘（24.03 新连接走 keyfile，老 ifcfg 是兼容层）、ip addr 看内核实际生效——改配置是 nmcli con mod 加 con up，mod 只改登记表，up 才把配置拍进内核，和 firewalld 的 --permanent 加 --reload 是同一条生效轴；
> nmcli 和 firewalld 是两条轴：nmcli 管'你是谁'，firewalld 管'包能不能过'——排障先问自己问题出在哪条轴上再选工具；
> 远程改主网卡 IP 等于自断 SSH，实验用 dummy 接口。」

## 附：同日加练 · Docker §二十二 容器安全加固（254，Docker CE 26.1.3）

### 八条基线（面试直接背）
最小镜像 / 非 root / 只读根 / 丢 capabilities / 资源限制 / 健康检查 / 日志轮转 / 端口只绑回环。

### HEALTHCHECK（容器自己会体检）
```bash
docker run -d --name hc-demo -p 127.0.0.1:18080:80 \
  --health-cmd='wget -qO- http://localhost/ >/dev/null || exit 1' \
  --health-interval=10s --health-retries=3 --health-start-period=5s nginx:1.27-alpine
docker inspect --format '{{.State.Health.Status}}' hc-demo    # → healthy
docker ps --format '{{.Names}} {{.Status}}' | grep hc-demo   # → Up 43 seconds (healthy)
```
- **`docker ps` 的 STATUS 列多出 `(healthy)` 括号**；`State.Health.Log` 留证：每 10 秒一条，ExitCode:0。
- alpine 镜像里**没有 curl**，探测命令要用 busybox 的 `wget`。

### 加固三件套 + errno 分类学
| 手法 | 命令 | 实测 |
|---|---|---|
| 只读根 | `--read-only` | `mkdir() "/var/cache/nginx/client_temp" failed (30: Read-only file system)` → Exited(1) |
| 非 root | `--user 1000:1000` | `mkdir() ... failed (13: Permission denied)` → Exited(1)；附警告 `user directive ... ignored` |
| 丢 cap | `--cap-drop ALL` | `CapDrop=[ALL] CapAdd=[]`；容器照常跑（18080 非特权端口） |

**★★ 同一句 `mkdir() failed`，errno 定病根**：
- **30 EROFS** = 文件系统只读（要写就挂 tmpfs）
- **13 EACCES** = 权限/属主不对（调 user 与目录属主）

🎯 30 = 柜子贴了封条；13 = 柜子是你的但钥匙不在手上。

### Docker ↔ K8s 安全对照
`--health-cmd`↔liveness/readiness 探针｜`--read-only`↔readOnlyRootFilesystem｜`--user`↔runAsNonRoot｜`--cap-drop`↔capabilities.drop｜`-m/-c`↔resources.limits｜restart policy↔Deployment 自愈｜`-p 127.0.0.1:…`↔Service+NetworkPolicy｜容器名 DNS↔headless Service。
